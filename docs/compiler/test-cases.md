# 结构化测试用例

## 源结构

`test-case` directive 只固定用例元数据；正文仍使用普通 Markdown：

```markdown
:::{test-case} 端到端时延测试
:id: TC-LATENCY-001
:priority: P0

**目的：** 测量固定路径上的端到端时延。

**前置条件：** 路径稳定，时间同步满足要求。

**步骤：**

1. 固定端点和路径；
2. 采集逐包时延 $T_i$；
3. 恢复环境并归档证据。

**判定：** 样本有效且满足已冻结阈值。
:::
```

短的段首加粗文本以 `:` 或 `：` 结束时，会成为一个语义字段名。也可以使用 directive
内的小标题定义字段。字段名不使用“目的、步骤”等固定词表，因此其他语言和文档类别
可以复用。第一个字段之前的内容作为用例说明；没有字段边界时，正文保持一个自由内容区，
兼容简单用例。

反引号继续表示命令、ID 和字段值；`$...$` 与 `$$...$$` 表示数学公式。字段内容可以是
段落、列表、表格、代码和公式，不需要在 Markdown 中编写 Word 行列或合并信息。

## 默认 DOCX 映射

默认 renderer 使用六列逻辑网格：

- 标题横向合并六列并居中；
- 用例 ID 和优先级在同一行形成两个“标签 + 值”组合；
- 普通字段使用一列标签和横向合并的五列内容区；
- 列表字段拆为逐项行，单独保留序号列；
- 字段名在整个列表范围内纵向合并；列表跨页时允许续页出现空的合并延续格；
- 标题和元数据作为连续重复表头，跨页后仍能识别所属用例。

六列只是默认 renderer 的结构选择，不进入 Markdown 语义。项目有不同输出契约时，可以
替换 renderer 或组合不同的表格 profile，而不改变源内容和 `TestCaseSection` IR。

## 提升到核心的能力

真实测试方案验证并提升了以下通用能力：

- `TableCellSpec.column_span` 与 `row_span` 的重叠和越界校验；
- 合并感知的列宽和行高计算；
- `TableRowSpec.prevent_split` 的单行分页约束；
- `w:t` 与 `m:t` 的统一文本测量；
- 固定布局下对逻辑网格、物理单元格宽度和合并宽度的同步写入。

测试用例的字段识别、分区 IR 和默认六列映射属于跨项目稳定语义，因此位于核心；具体
场景、DUT、判据和记录字段的内容仍属于源文档或项目实现。
