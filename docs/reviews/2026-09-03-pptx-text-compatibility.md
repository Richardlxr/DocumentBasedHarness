# 模板文字换行：原因、修复与适用边界

## 结论

本次 `SJTU` 异常不是由编译器改变文字或移动文本框引入的。修复前，源模板和编译结果的
该形状 XML 一致，原模板在相同 LibreOffice 环境也发生同样换行。更可能是字体替代与
播放器文字排版/导入行为共同作用。尚未取得原字体、原作者 PowerPoint 环境的对照，
不能把责任百分之百归到某一种字体或某个软件缺陷。

编译器仍有工程责任：原生复制保证了文件元素的保留，但之前没有充分检查被继承文字的
字体、空间和自适应风险；上一轮视觉 QA 也漏检了品牌短字。修复目标是降低并及时发现
兼容性缺陷，不承诺所有模板在任意播放器下像素一致。

## 已核实证据

- 输入：`5.浩瀚星河-迮佳.pptx`，可见第 15 页，`slideLayout15.xml`，shape 11。
- 内容为单段、单 run 的 `S J T U`，没有显式换行；18pt 粗体，继承微软雅黑。
- 原文本框宽 61.23pt，左右内边距均为零，`wrap="square"`、`spAutoFit`。
- 修复前源形状与合成后形状 XML 一致；同机渲染原模板也将 U 换到下一行。
- 本机编译测量替代字体为 Verdana Bold，估算宽度（含 8% 余量）73.44pt。
  从原始与修复后的 PDF 字体记录核实，播放器实际用的是 HiraginoSans-W7；
  修复后 PDF 中实际文字水平范围约 71.41pt，也大于原文本框。
  早期 `fc-match` 的 Skia 结果只是预测，不能作为实际播放字体的结论。
- 只设置 `wrap="none"` + `spAutoFit` 仍在该 LibreOffice 中换行；按测量宽度生成文本框、
  关闭换行及自动适配后，实际 PDF/PNG 中四个字母处于同一行。原位置、文本、字号和高度保留。

预览软件：LibreOfficeDev 26.8.0.0.alpha0。原模板文件未改写；修复写在样式配置和编译器，
再重建探针成品。可复核文件位于私有测试 run：

- `qa/sjtu-galaxy-wrap/source-slide15-1.png`：原模板复现。
- `qa/sjtu-galaxy-wrap/diagnosis.txt`：前后诊断。
- `qa/sjtu-galaxy-wrap/fixed-text-geometry.json`：PDF 单行坐标与 PPTX 18pt 记录。
- `build/previews/sjtu-galaxy-2.png`、`build/sjtu-galaxy.pptx`：修复成品。

## 通用改进

1. `style-inspect` 增加 `text_layout`；编译报告增加 `native_text_diagnostics`。
   所有被保留的原生文字均检查换行、自适应、可用宽度与字体替代，包含粗斜体测量。
   告警是检查线索：正常多行文本也可能有宽度压力，不能自动判为缺陷。
2. `single_line` 是显式的样式契约，适用于任何模板中确认应为单行的简单品牌标签。
   不根据 SJTU、文件名、语言或短字长度做特殊判断；普通文字保持源设置。
3. 单行修复按测量宽度扩宽，保留字号和左侧位置；扩宽后检查画布边界、生成内容碰撞、
   新增装饰碰撞。复杂多段/混合 run、旋转、分组内文字等拒绝自动修复，避免静默破坏。
4. QA 对照原稿与成品的同环境渲染，检查所有文字层；记录软件和字体环境。
   出现编译引入的变化时修编译器；原稿同样异常时继续隔离字体与播放器因素。

对九份模板已经选中的样式面进行了兼容性扫描：保留的原生文字共两个，宽度压力命中
该 SJTU 对象。其余选中品牌大多为图形。**这不等于九份模板的 225 个源页全部没有问题**，
也不等于未采用的正文文字已经通过检查。完整记录见 `qa/native-text-compatibility.json`。

回归使用独立构造的品牌文字，不依赖私人模板，覆盖风险发现、原文不自动改写、单行修复、
不缩字号、原输入不变、拒绝显式多行，以及扩宽后的越界/内容/装饰碰撞。

## 模板在哪一步问

| 场景 | 时点与处理 |
|---|---|
| 用户已经给定单个模板 | Gate 1 记录选择，不重复询问是否使用 |
| 用户给模板合集、尚未决定 | Gate 1 记录 deferred；故事线及粗大纲后给少量候选，再确认样张 |
| 未指定模板 | 在契约中提出默认样式，一起接受，无须独立提问 |
| 首次适配原生模板 | 粗大纲后、批量细化前展示真实样张和重要差异，记录 deck_appearance |
| 用户明确委托样式审阅 | 可省略该轮；大纲细化委托不能隐式充当样式委托 |
| 同一 run 的同样式后续内容变更 | 复用当前样式接受，不反复确认 |
| 更换字体/品牌/颜色等重要调整 | 更新样式及差异说明，重新展示样式，不重审未变的故事线 |
| 恢复预期效果的意外换行修复 | 直接修复、重编译与 QA；最终交付仍按原流程验收 |

CLI 校验顺序、样式版本与展示文件，但不认证用户身份，也无法认证 agent 是否确实将
样张展示给用户。`agent_attested` 的既有信任边界不变。风格模板的密度/结构规则不在本次范围。

## 规范依据

[Microsoft DrawingML BodyProperties](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.bodyproperties?view=openxml-3.0.1)
定义换行、文本框内边距与自适应设置；
[NormalAutoFit](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.normalautofit?view=openxml-3.0.1)
说明自动缩放文本的语义。文件中的设置仍需由播放器实现；本次“仅 no-wrap 仍异常”的判断
来自实际对照实验，不以文档语义替代渲染证据。
