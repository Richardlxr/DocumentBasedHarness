# DocumentBasedHarness

> **把一堆材料，变成一场能说服人的汇报。**
> 材料进来，事实打底，你拍板两次，幻灯片 / 网页 / 报告一起出来——
> 每个数字都有出处，语言风格你说了算，每次修改只动该动的那层。

---

## 这是个什么东西？

周五下午，你手里有：一份 CSV、几段实验日志、一张结果截图、半篇没写完的说明。
下周三，你要用这些说服客户：这个方案值得上。

一般的做法是打开 PPT 开始搬字。搬着搬着就会发现：数字对不上、逻辑断在第三页、
报告和幻灯片各说各话、写出来的话一股 AI 腔。

这里的做法不一样——一个**汇报编译器**。它先把材料读成一份**带出处的事实库**，
跟你对齐"讲给谁、要什么效果、说什么腔调"，设计一条**故事线**（这两步你拍板），
然后把同一个故事一次编译成三种成品：

| 成品 | 长什么样 |
|---|---|
| `deck.pptx` | 幻灯片：每页一个观点，标题就是结论；数据卡片、图表、示意图的数字**直接从事实库取**——想写错都没机会 |
| `deck.html` | 网页版：单文件、离线双击可开，带出场动画（先结论、再证据、最后 so-what）和演讲者备注 |
| `report.md` + `report.docx` | 详版报告：书面语完整展开，Markdown 是正主，Word 是一键编译的排版成品 |

两个硬承诺：

- **数字不会飞。** 成品里出现的每个数字都能一路点回源文件的某一行；从图上
  读出来的数字会被老实标注为"估读"，只靠估读撑起来的结论会被点名。
- **改哪层，修哪层。** 材料变了不会从头重来：系统知道每层产物从哪个上游生成，
  只把受影响的层标脏重做，你确认过的内容原样保留。

## 工作流：从材料到成品

全流程就一条线，两处你拍板，一处你验收：

```text
 ①交材料      ②对齐（拍板）        ③故事（拍板）      ④双投影        ⑤渲染+验收
 ────────►  ───────────────►  ───────────────►  ──────────►  ──────────────►
 sources      事实库+沟通契约      故事线             幻灯片计划      pptx/html/docx
              受众·目标·语言风格   每拍一句话         报告计划        机器体检+你通读
                                    │
                                    └─ 不满意？沿链定位问题在哪一层，只修那一层
```

**① 交材料** —— 东西丢进 `sources/`（CSV、日志、PDF、图、markdown 都行），AI
逐条提取成事实库：每条带出处，数字带结构化锚点，从图上读的标"估读"。

**② 对齐（你拍板）** —— AI 推断一份沟通契约：给谁看、想达成什么、什么语言、
**什么语言风格**（见下面 FAQ 第一条）、什么绝对不能做（"不要黑底"会落到代码级
强制）。看摘要、改细节、放行：`comh confirm brief`。没过这关，后面一步都动不了。

**③ 故事（你拍板）** —— AI 把故事线排成你能一眼看懂的逻辑链，每个论断挂着
证据状态（有据 / 部分 / 假设 / 缺料——宁可诚实，不编引用）：

```text
01 为什么要关心尾延迟   02 我们怎么验证的    03 P99 降了 18.2%
04 但高负载有边界       05 原因是缓存共用    06 建议灰度 + 专项
```

你确认逻辑链：`comh confirm narrative`。

**④ 双投影** —— 同一个故事，两种组装（不是互相压缩）：幻灯片按"现场 30 分钟
怎么讲"投影（口语短句），报告按"会后细读怎么展开"投影（书面完整句）。数据卡片、
图表、mermaid 示意图、图标在这一步就位。

**⑤ 渲染 + 验收** —— 纯代码出成品，出厂前过机器体检（引用链、数字一致性、
硬约束、图语法、元素遮挡、AI 腔……每条问题标注该修哪个文件）。体检不是
自觉：save / confirm / render 都会**先跑校验、有 error 直接拒绝**。**最后一步
永远是你通读**——机器管下限，风格和分寸你拍板；你点头后
`comh deliver` 把验收落进记录（钉住成品指纹，重渲染自动作废、需重新验收）。

**之后不满意？** 一句话说清哪里不对：`comh evidence-pack deck P05` 切出那一页的
完整证据链（页面→故事→论断→证据→源文件），六问诊断定位病根在哪层，只修那层。
分层话术见[用户指南 §8.5](docs/user-guide.md)。

## 三个常见问题

### 怎么锚定语言风格？

风格是**Gate 1 就对齐的契约**（`brief.voice`），不是事后祈祷。两条路：

1. **你给样本**：贴两三句自己平时汇报的原话，全部写作向它对齐——比任何形容词都准；
2. **AI 出几版你选**：不给样本时，AI 用一条真实内容按 2-3 个风格档各写一版，
   你选一版、口头微调（"再正式一点""数字前置"）到满意为止。

而且**幻灯片和报告分面设置**：deck 是说出口的话（短句、可念），报告是书面语
（完整句、严谨展开），`voice.deck` / `voice.report` 各自覆盖全局基调。选定后，
`comh validate` 的风格检查**执行你选的风格**（可放行破折号金句、追加禁词），
机器清零后**仍要你通读验收**——lint 是下限，你才是终点。

### 怎么调整所需样式？

按介入深度三档，随时可换、不用改代码：

| 深度 | 做法 |
|---|---|
| 换个现成主题 | `deck.style.template: slate-tech`（内置三套） |
| 微调 | `deck.style.tokens_override: {colors: {accent: ...}, sizes: {body: 26}}` |
| 用你的品牌 | `comh theme-from-pptx 你的模板.pptx --name brand` 提取你的色板和中英文字体，生成 run 级主题，`template: brand` 即用 |

单个任务还能自带 `runs/<name>/themes/` 覆盖仓库级主题。

### 不调样式的话，默认拿到的是白板吗？

不是。默认就是一套**成体系的设计储备**，开箱即用：

- **三套内置主题**（tier1-light / slate-tech / midnight，palette+字号+中英字体）；
- **编辑级排版系统**：显示级大标题、眉标（kicker）、页码页脚、发丝线、页顶强调条、
  角部浅色装饰；
- **内容构件**：大数字 KPI 卡（渲染时从证据取数）、原生图表、mermaid 示意图
  （确定性布局）、底部结论条、展开式要点卡；
- **5,130 个语义图标**（MIT），按名字引用，颜色自动跟主题；
- **出厂体检**：十类检查 + 遮挡碰撞检测（pptx 和 html 双面）。

什么都不配置，出来的也是一套完整、体面、防溢出的商务汇报——主题系统决定的是
"换成什么样"，不是"有没有"。

## 快速开始

```bash
git clone git@github.com:Richardlxr/DocumentBasedHarness.git
cd DocumentBasedHarness
python -m venv .venv && .venv/bin/pip install -e '.[dev]'

# 看现成的：一个完整的客户汇报样例
open runs/sample-cache-latency/build/deck.html     # 浏览器里翻页、点动画、按 S 看备注
open runs/sample-cache-latency/build/deck.pptx

# 开你自己的
.venv/bin/comh init-run runs/my-report    # 材料丢进 sources/，然后按上面五步走
```

图形（mermaid 示意图）渲染需要 draw.io Desktop；macOS 上：
`export DRAWIO_CLI="/Applications/draw.io.app/Contents/MacOS/draw.io"`
（版本与内置 pin 不一致时再加 `DRAWIO_ACCEPT_VERSION=<版本号>`）。

## 凭什么信它

- **两道关卡，代码强制。** 契约和故事线没经你确认，下游命令直接拒绝执行；
  确认后偷改文件会自动作废确认——对齐不靠模型自觉。
- **验收有清单。** 147 个自动化测试 + 十类出厂体检：悬空引用、无据结论、
  数字漂移、静默丢内容、图语法错误、图标名写错、元素遮挡、越界、AI 腔、密度超载…
- **AI 做判断，代码管合同。** 该灵活的地方（叙事模式、语言风格、视觉主题）
  是开放的词汇表；该死硬的地方（Gate、溯源、硬约束）是确定性代码。

## 设计原则（八句话）

内容逻辑先于视觉设计 · 报告和幻灯片是同一故事的两个投影 ·
词库只供词汇不划边界（风格、主题、叙事皆是）· 用户硬约束 > 偏好 > 已确认 spec >
推断 > 默认 · 保存显式产物而非隐藏思维链 · 证据→论断→故事→投影→成品步步可回溯 ·
修复在归属层进行 · 观众是最终消费者——优化他们记住了什么，不是你想倒什么
