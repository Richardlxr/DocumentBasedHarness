# DocumentBasedHarness

> **把一堆材料，变成一场能说服人的汇报。**
> 材料进来，事实打底，你拍板两次，幻灯片 / 网页 / 报告一起出来——
> 每个数字有出处，样式、动画、素材、语气都靠说，每次修改只动该动的那层。

---

## 这是个什么东西？

周五下午，你手里有：一份 CSV、几段实验日志、一张结果截图、半篇没写完的说明。
下周三，你要用这些说服客户：这个方案值得上。

一般的做法是打开 PPT 开始搬字。搬着搬着就会发现：数字对不上、逻辑断在第三页、
报告和幻灯片各说各话、写出来的话一股 AI 腔。

这里的做法不一样——一个**汇报编译器**。它先把材料读成一份**带出处的事实库**，
跟你对齐"讲给谁、要什么效果、说什么腔调"，设计一条**故事线**（这两步你拍板），
然后把同一个故事一次编译成三种成品：

| 成品 | 长什么样 |
|---|---|
| `deck.pptx` | 幻灯片：每页一个观点，标题就是结论；数据卡片、图表、示意图的数字**直接从事实库取**——想写错都没机会 |
| `deck.html` | 网页版：单文件、离线双击可开，带出场动画（先结论、再证据、最后 so-what）、数字跳动和演讲者备注 |
| `report.md` + `report.docx` | 详版报告：书面语完整展开，Markdown 是正主，Word 是一键编译的排版成品 |

两个硬承诺：

- **数字不会飞。** 成品里出现的每个数字都能一路点回源文件的某一行；从图上
  读出来的数字会被老实标注为"估读"，只靠估读撑起来的结论会被点名。
- **改哪层，修哪层。** 材料变了不会从头重来：系统知道每层产物从哪个上游生成，
  只把受影响的层标脏重做，你确认过的内容原样保留。

## 工作流：五步走，每一步都能插话

全流程一条线，两处你拍板，一处你验收。**每一步都有属于那一步的话可说**——
下面每节末尾的"这时候你可以说"就是提示词样本，照着说就行，不需要碰任何
配置文件或命令（那些是 agent 的落笔处，留档审计用）。

```text
 ①交材料      ②对齐（拍板）        ③故事（拍板）      ④双投影        ⑤渲染+验收
 ────────►  ───────────────►  ───────────────►  ──────────►  ──────────────►
 sources      事实库+沟通契约      故事线             幻灯片计划      pptx/html/docx
              受众·目标·语言风格   每拍一句话         报告计划        机器体检+你通读
                                                    版式·素材·动画
                                    │
                                    └─ 不满意？沿链定位问题在哪一层，只修那一层
```

### ① 交材料

东西丢进 `sources/`（CSV、日志、PDF、图、markdown 都行），AI 逐条提取成事实库：
每条带出处，数字带结构化锚点，从图上读的标"估读"。

这时候你可以说：

- "日志里 8 月 12 号那次实验重点看，其他只是铺垫"
- "这张图是草图，别当数据用"
- "这份 PDF 是官方口径，跟我的实验记录冲突时以它为准"

### ② 对齐（你拍板）

AI 推断一份沟通契约：给谁看、想达成什么、什么语言、**什么语言风格**、什么绝对
不能做（"不要黑底"这类硬约束会落到代码级强制，不是提示词里祈祷）。看摘要、
改细节、放行。没过这关，后面一步都动不了。

**语言风格就在这一步定**，比任何事后润色都管用。两条路：

1. **你给样本（最准）**：贴两三句自己平时汇报的原话，之后所有文字向它对齐——
   "再正式一点""数字前置"这类口头微调随时生效；
2. **AI 出几版你选**：不给样本时，AI 用一条真实内容按 2-3 个风格档各写一版，
   你选一版慢慢调。

风格分面设置：幻灯片是说出口的话（短句、可念），报告是书面语（完整句、严谨
展开），两个可以各要各的腔调。选定后，机器的风格检查**执行你选的风格**——
你放行过的破折号金句不再报，你加的禁词一律拦。

这时候你可以说：

- "照我平时汇报的口气来：（贴两三句原话）"
- "幻灯片口语化，报告书面化"
- "数据前置，每段先给数再解释"
- "别用'赋能''抓手'这类词"（会进禁词表，机器拦）
- "不要黑底"（代码级强制，违反直接拒绝渲染）

### ③ 故事（你拍板）

AI 把故事线排成你能一眼看懂的逻辑链，每个论断挂着证据状态（有据 / 部分 /
假设 / 缺料——宁可诚实，不编引用）：

```text
01 为什么要关心尾延迟   02 我们怎么验证的    03 P99 降了 18.2%
04 但高负载有边界       05 原因是缓存共用    06 建议灰度 + 专项
```

这时候你可以说：

- "第二拍挪到最后，先给结果再讲过程"
- "这条证据不够硬，先标成假设"
- "结尾要一句客户能带走的话"

### ④ 双投影：版式、素材、动画都在这里说

同一个故事，两种组装（不是互相压缩）：幻灯片按"现场 30 分钟怎么讲"投影，
报告按"会后细读怎么展开"投影。**版式、图表、背景图、素材、动画顺序在这一步
各就各位**——都是对话里定的，详见下面两节（[样式](#样式从选到造)、[动画](#动画说什么出什么)）。

这时候你可以说：

- "这页左右分栏，左边放架构图"（hero_split 版式）
- "他的成长历程做成时间轴，四个节点"（timeline 版式）
- "两个方案做左右对比"（versus 版式，左右栏名字你起）
- "这页要一张全幅背景图压住，文字浮在中间卡片上"（fullscreen_backdrop 版式）
- "关键数字都做成大数字卡，一眼看到 18.2%"
- "我想展现他的成长历程，需要什么素材？怎么呈现比较好？去检索一下？"

最后这句会触发**素材流程**：agent 先提案（呈现方式 + 素材清单 + 建议来源），
你点头才联网检索；找来的图优先公有领域 / CC 许可，全部落盘进任务工作区并
登记出处与许可，渲染只读本地文件——离线可复现，出处随时可查。

### ⑤ 渲染 + 验收

纯代码出成品（渲染时没有模型在环），出厂前过机器体检：引用链、数字一致性、
硬约束、图语法、元素遮挡、AI 腔、主题对比度……每条问题标注该修哪个文件。
体检不是自觉：save / confirm / render 都会**先跑校验、有 error 直接拒绝**。

**最后一步永远是你通读**——机器管下限，风格和分寸你拍板；你点头后
`comh deliver` 把验收落进记录（钉住成品指纹，重渲染自动作废、需重新验收）。

这时候你可以说（**单页微调，只动那一页**）：

- "P03 标题太长，收一收"
- "P05 背景图换一张更暗的"
- "结尾页的强调色改成我们的品牌蓝"

**之后不满意？** 一句话说清哪里不对：`comh evidence-pack deck P05` 切出那一页的
完整证据链（页面→故事→论断→证据→源文件），六问诊断定位病根在哪层，只修那层。
分层话术见[用户指南 §8.5](docs/user-guide.md)。

## 样式：从选到造

**全部靠说**。你现在看到的配置和命令是 agent 的落笔处；你看到的永远是成品。

| 你说 | 会发生什么 |
|---|---|
| "换个深色的" / "要酷一点" / "像杂志" | agent 提 2-3 个方向（各一句话气质），你挑一个，浏览器里看效果 |
| "给我定制一套主题"（描述气质："赛博霓虹""水墨留白"） | 内置没命中时，agent **现场创作**整套配色/字号/字体，自动过可读性体检（正文对比度不达标不出厂），渲染样张你挑 |
| "强调色改成品牌蓝，标题再大点" | 按次微调重渲染，秒级往返 |
| "用我们的模板"（丢一个 pptx 或给链接） | 提取你的色板和中英文字体生成品牌主题，幻灯片/网页/报告三端换装 |
| "这页放一张他年轻时的照片？" | agent 提素材方案，你点头后才检索、落盘、登记出处，出版本你挑 |
| "这套先出两页样板，我看看感觉" | 先渲染 1-2 页样张对齐，认可了再做整套——方向错了不至于整场返工 |

五个内置方向兜底，从严谨到吸睛：

| 方向 | 气质 | 适合 |
|---|---|---|
| tier1-light | 干净留白、蓝笔标注 | 学术汇报、评审 |
| slate-tech | 浅石板底、靛蓝 | 客户技术评审 |
| midnight | 深色舞台 | 大屏发布、路演 |
| poster-pop | 海报波普：奶油纸+朱红+超大字 | 创意提案、发布周 |
| gallery-noir | 画廊黑金：暖黑+象牙+鎏金衬线 | 颁奖、作品集 |

创意和艺术向是一等公民，不是附带功能。气质没被命中就现场生成一套——
AI 负责创作，机器负责体检，生成是正门不是变通。

**背景图**也是一等能力：任何一页可以要一张背景图，系统实测图片与文字的
对比度，不够就自动加深蒙层（文字永远可读，这是出厂检查，不是建议），
图片缩放压缩后内联进单文件 HTML，不会把文件撑爆。

**边界也诚实**：效果超出当前版式引擎（比如完全自由的手工排版）时，agent
会直说"这个做不到"，不硬凑——版式的确定性保证（不溢出、不遮挡）不为此让步。

## 动画：说什么，出什么

动画在这套系统里是**沟通决策**，不是装饰：先亮结论还是先铺证据、哪句话值得
单独一次点击，直接决定观众记住什么。所以动画也是在对话里定的：

| 你说 | 会发生什么 |
|---|---|
| "这三个要点一个一个出" | 每点一次点击，讲完一条再出下一条（网页+PPTX 同语义） |
| "先亮结论，再一条条给证据" | 结论条先出，证据卡逐步步进 |
| "最后强调这一条" | 该条高亮，其余不动 |
| "翻页用 fade" | 翻页过渡切换：fade / push / wipe / cut |

网页版还自带两层**微动效**，不用你说、自动就有：

- KPI 大数字进场时从 0 跳到位（约 0.8 秒），柱状图从 0 长出来；
- 观众系统开了"减少动态"（prefers-reduced-motion）时全部自动关闭，只剩静态终值。

动词表故意很小（出场 / 淡入 / 强调 / 高亮 × 点击 / 同时 / 延时），换来的是
**网页和 PPTX 执行同一套语义**——同一份计划，两端长一个样，不会网页有动画、
打开 PPT 全没了（PPTX 端动画是实验性开关，网页版默认全开）。做不到的效果
（视差滚动、自动播放的剧场式演出）agent 会直说，不硬凑。

## 不调样式的话，默认拿到的是白板吗？

不是。默认就是一套**成体系的设计储备**，开箱即用：

- **五套内置主题**（palette + 字号 + 中英字体，学术到创意艺术全覆盖）；
- **五种版式原型**：标准图文页 / 图文分栏（hero_split）/ 全幅背景+悬浮卡
  （fullscreen_backdrop）/ 时间轴（timeline，3-4 节点）/ 双栏对比（versus）；
- **编辑级排版系统**：显示级大标题、眉标（kicker）、页码页脚、发丝线、页顶
  强调条、角部浅色装饰；
- **内容构件**：大数字 KPI 卡（渲染时从证据取数）、原生图表、mermaid 示意图
  （确定性布局）、底部结论条、展开式要点卡；
- **5,130 个语义图标**（MIT），按名字引用，颜色自动跟主题；
- **出厂体检**：十类检查 + 遮挡碰撞检测（pptx 和 html 双面）。

什么都不配置，出来的也是一套完整、体面、防溢出的商务汇报——主题系统决定的是
"换成什么样"，不是"有没有"。

## 快速开始

```bash
git clone git@github.com:Richardlxr/DocumentBasedHarness.git
cd DocumentBasedHarness
python -m venv .venv && .venv/bin/pip install -e '.[dev]'

# 看现成的：渲染示例 run（一个完整的客户技术汇报），然后浏览器里翻页
.venv/bin/comh render deck-html --run runs/sample-cache-latency
open runs/sample-cache-latency/build/deck.html   # 方向键翻页、点击步进动画、按 S 看备注
.venv/bin/comh render deck --run runs/sample-cache-latency && open runs/sample-cache-latency/build/deck.pptx

# 开你自己的
.venv/bin/comh init-run runs/my-report    # 材料丢进 sources/，然后按上面五步跟 agent 走
```

图形（mermaid 示意图）渲染需要 draw.io Desktop；macOS 上：
`export DRAWIO_CLI="/Applications/draw.io.app/Contents/MacOS/draw.io"`
（版本与内置 pin 不一致时再加 `DRAWIO_ACCEPT_VERSION=<版本号>`）。

## 凭什么信它

- **两道关卡，代码强制。** 契约和故事线没经你确认，下游命令直接拒绝执行；
  确认后偷改文件会自动作废确认——对齐不靠模型自觉。
- **验收有清单。** 169 个自动化测试 + 十类出厂体检：悬空引用、无据结论、
  数字漂移、静默丢内容、图语法错误、图标名写错、元素遮挡、越界、AI 腔、
  密度超载、主题对比度、素材出处……
- **AI 做判断，代码管合同。** 该灵活的地方（叙事模式、语言风格、视觉主题、
  动画编排）是开放的词汇表；该死硬的地方（Gate、溯源、硬约束、可读性下限）
  是确定性代码。

## 设计原则（八句话）

内容逻辑先于视觉设计 · 报告和幻灯片是同一故事的两个投影 ·
词库只供词汇不划边界（风格、主题、叙事、动画皆是）· 用户硬约束 > 偏好 >
已确认 spec > 推断 > 默认 · 保存显式产物而非隐藏思维链 ·
证据→论断→故事→投影→成品步步可回溯 · 修复在归属层进行 ·
观众是最终消费者——优化他们记住了什么，不是你想倒什么
