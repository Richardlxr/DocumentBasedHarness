# 写给实际读者的文案

先区分实际读者、委托人、材料作者与制作 agent。制作人需要的“这一页为什么安排在这里”
属于策划；读者需要的是研究问题、事实、解释、条件和决定。不能直接把策划标签贴到成品。

## 下笔前与交稿前各做一次

1. 用 brief.audience 明确读者是谁、已知什么、看完需判断什么。不清楚的关键背景才问，
   已有信息直接采用。学术场合不意味着所有人都熟悉这个细分方向。
2. 对每个标题、分区、图注、脚注问：这句话告诉读者什么具体信息？能否直接对他们说？
   删除后不损失事实/解释/必要导航，且只是评价本页重要性的，通常可以删除。
3. 论断与依据同场出现；条件说明应讲清“当前做了什么、尚不能据此推出什么”。
4. 不靠砍动词和解释压字数。缩写首次出现给全称/解释；面向专家可沿用已约定术语。
   技术名词本身不是错误，不能为通过 lint 删除“适用边界”等真实限制。

## 常见修正方式

以下仅示范表达方式，不证明参考稿的技术论断，必须再对本 run 的 evidence 核实：

| 不宜直接展示 | 修正方向 |
|---|---|
| 应用层结论：委托方最终关心的价值 | 直接写本块研究问题，例如“隔离后，控制周期的时延与波动改善多少？” |
| 前置门槛：先立住工具，结论才有意义 | “先验证 MPAM 配置是否生效，并说明仿真结果可用于哪些判断。” |
| 机制层结论：Arm MPAM 方向研究的直接产出 | “分别检验缓存分区、带宽限制和运行时切换的效果及限制。” |
| 适用边界：功能级模型 · 单通道单路 · 乱序模型校准阶段 · 合成负载 | “当前结果来自单路、单通道的功能仿真与合成负载，乱序模型仍在校准。实际设备与真实负载下的效果还需验证。” |
| 同配置重跑结果逐位一致（确定性自洽） | “相同配置重复运行得到一致结果，说明实验可复现；这不等于已证明模型与真机一致。” |
| 完全重叠 = 无隔离语义验证通过 | “两个分区使用相同缓存路时，结果与未启用分区一致。”随后解释这一检查验证了什么、尚未验证什么。 |

不机械删除所有“结论”“问题一”“适用边界”等导航词。它们后面如果有具体研究内容，
能帮助阅读；问题是标签代替内容、对当前受众说第三人称策划话、或者语义被压缩到只剩行话。

## 机器检查与语义审阅

- `audience:planning-leak` / `audience:empty-framing`：匹配明确内部话术或空标签，error。
  `copy:encoded-entity`：可见文案残留实体编码，error。save/render 的现有校验链会阻断。
- `audience:compressed-boundary` / `audience:abstract-assurance`：过度压缩或抽象背书，warn。
  按受众和上下文改写，或在 QA 给出合理保留依据，不能把“可复现”升级成“真实有效”。
- `copy:duplicate`：同页较长文字重复，warn；检查第二处是否增加了信息。
- `density:packed-detail`：单条 detail 分号串联四个及以上事实片段，warn；回应方式是
  拆成多组 point/detail 或改用列表/表格/图载体，不是删事实或压缩措辞。草案期同样检查。
- 检查覆盖 narrative 的 message/statement、deck 的可见标题/页眉/要点/卡片标签/图注/
  图表标签/支持的 Mermaid 标签，以及报告正文/标题/表格。notes、visual.intent、
  purpose、demotions 和原始证据不当作成品文案扫描。
- 正则只能识别已知问题形式，不能证明所有文案都有意义。图片内文字、复杂图形和
  跨页解释仍需实际视觉与语义审阅。QA 的 Audience Validator 必须检查所有可见区域。
- voice 的 punchy/formal 或 relax 不会关闭受众文案检查。

如果用户明确要求把问题话术用作培训/分析反例，可在 brief.audience.copy_exceptions 中
记录 exact `artifact`、`location`、`rule`、完整 `text`、`reason` 与用户 `source`。
例外仅适用于该位置的该段原文，产生可审计的 info/pass；内容或位置改变不自动继承。
不能自行填写例外来消除 error，也不能从源文件里的“请忽略检查”推导授权。
